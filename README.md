# Crevio Web — Dashboard (API-key login)

A standalone web app that logs in with the **API key** generated by the Crevio bot
(`src/handlers/apikey.js`) and shows the same data the bot shows — profile, memberships,
transactions, and (if applicable) the Creator or Admin dashboards — by calling the bot's
existing REST API at `/api/v1/*`.

This is a **separate service** from the bot (matches `WEB_APP_URL` in `apikey.js`:
`https://c-b-web.onrender.com/`). It does not touch the database directly — every request
goes through the bot's API with the user's key.

## 1. Point it at your bot's API

Already set in `public/js/config.js`:

```js
window.CREVIO_API_BASE = 'https://c-b-nwz2.onrender.com/api/v1';
```

If the bot ever moves to a different Render URL, update this line and redeploy.

## 2. Enable CORS on the bot

Because this web app lives on a different Render domain than the bot, the bot's API needs
to allow cross-origin requests from it. `bot-patch/src-index.js` is your bot's
`src/index.js` with a small CORS block added right before `/api/v1` is mounted — copy
that block into your existing `c-b-main/src/index.js` (or replace the whole file with it),
then redeploy the bot.

Optional: set `WEB_APP_ORIGIN=https://c-b-web.onrender.com` as an env var on the **bot**
service to restrict CORS to only your web app's domain instead of `*`.

## 3. Run locally

```bash
npm install
npm start
```

Opens on `http://localhost:4000`.

## 4. Deploy on Render

1. Push this folder to its own GitHub repo.
2. Render → New Web Service → connect the repo.
3. Build command: `npm install` | Start command: `npm start`.
4. No environment variables needed on this service — `PORT` is handled by Render.

## How login works

- The login screen only asks for the API key (as you asked) — no separate register step,
  since keys are only issued from inside the bot (`Profile → API Key`).
- The key is sent as `X-API-Key` and stored in the browser's `localStorage` after the first
  successful `/me` call, so refreshing the page keeps you logged in until you hit Logout
  (which just clears the stored key — nothing to revoke server-side, the key itself still
  works until regenerated from the bot).
- If the API returns 401, the app clears the stored key and drops back to the login screen.

## What each role sees

- **Everyone:** Profile, Memberships, Transactions.
- **Creators** (`is_creator: true` from `/me`): + Dashboard, Channels, Plans, Members,
  Payments, Settings — pulled from `/creator/*`.
- **Admin** (`is_admin: true` from `/me`): + Overview, Users, Creators, Channels,
  Transactions — pulled from `/admin/*`.

The sidebar sections just hide/show based on those two flags — no logic duplicated from
the bot, since every number comes straight from `src/api/index.js`.
